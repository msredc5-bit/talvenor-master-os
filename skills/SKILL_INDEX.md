# Skill Index — canonical vs mirror copies

Generated by hand from a repo-wide comparison (Phase 1, Unified OS,
2026-11-22); re-verified by diff in Phase 2 (2026-11-25). 17 skill
stems exist in more than one copy. Rule: the **engine copy is
canonical**; a section copy is a mirror. A mirror is replaced by a
pointer file when it is **byte-identical** to the canonical copy, or
**near-identical with a lossless merge** (the differing bits folded
into the canonical copy first). The pointer is left at its path
because the department STAFF.md tables reference that path. A mirror
whose content **differs substantially** is kept as-is and listed below
— never delete a skill whose content differs. (Phase 2 corrected one
Phase 1 note: the kit-qa pair differed on line 76, not line 71 as
first written — the audit had the right line.)

Why kept (Phase 2, 2026-11-25 — applies to all 12 rows above):
- Merge is not lossless: folding a section copy into its engine copy
  would be a content rewrite (45–113 changed lines each), not a dedup
  — the section copies carry agent bindings, "Tools used" / "Worked
  example" / "Never does this" sections, and sometimes unique facts
  the engine copy lacks.
- Rename is not safe: `scripts/check_phase7.py` check #3 derives every
  section skill filename from its agent filename
  (`fname[:-3].replace("_", "-") + ".md"`, "23 section skill files
  exist (one per agent)") — a section skill renamed off its agent's
  stem breaks that structural invariant. It is a computed derivation,
  not a string reference, so there is nothing to "update" without
  weakening the check to a hand-maintained map. Renaming the engine
  copy instead would not resolve the collision either (the section copy
  would still share the stem) and would break `registry.json`
  `skill_file` paths, check #4 (Agency mapped staff), and STAFF.md.
- The remaining ambiguity is bounded: by-name lookup is deterministic
  — the engine copy wins, because `SKILL_ROOTS` lists engine roots
  before section roots. Verified by probe 2026-11-25 for all 17 stems:
  `load_skill(<stem>)` returns the engine copy every time; a section
  copy is reachable only by explicit repo path. (The finder now also
  warns on ambiguous bare names — see `skill_finder.py`.)

## Cross-department same-name skills

`caption-writer`, `content-planner`, and `publish-prep` exist in both
the Agency engine and the Content engine with different content. They
are separate skills that happen to share a stem. By-name lookup does
collide: `load_skill(<stem>)` returns the FIRST index entry, which is
the Agency engine copy (Agency engine roots precede Content engine
roots in `SKILL_ROOTS`) — the Content engine copy is reachable only by
explicit repo path. Do not merge them by name alone.

## How to update

When a new skill is added in two places, compare the files first
(`diff`). Byte-identical, or near-identical with a lossless merge
(fold the differing bits into the engine copy first) → replace the
section copy with a pointer to the engine copy and add a row to
"Deduped". Substantially different → keep both, record the verified
diff size and the reason, and add a row to "Kept". Do not rename a
section skill off its agent's stem — `scripts/check_phase7.py` check
#3 derives the skill filename from the agent filename.
